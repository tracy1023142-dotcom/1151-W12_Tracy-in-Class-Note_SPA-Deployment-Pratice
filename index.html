    1Define the Product定義產品

    What are we building, what is it built with, and how is it delivered? 我們要做什麼？用什麼來做？以什麼方式提供？

    Product flow產品流程

    Team Project (TP)團隊專案（TP）= Product: App · Software · Application＝產品：App · 軟體 · 應用程式
    →
    built with BNA Agent以 BNA Agent 製作Business News Analysis商業新聞分析
    →
    Website → SaaS網站 → SaaSSoftware as a Service軟體即服務

    Key terms關鍵詞

    Term名詞Meaning意義
    TPTeam Project. The product we build (app / software / application).團隊專案，即我們要開發的產品（App／軟體／應用程式）。
    BNA AgentBusiness News Analysis Agent, the AI agent used to build the product.商業新聞分析代理，用來製作產品的 AI 代理。
    SaaSSoftware as a Service. Software delivered through a website, with no installation needed.軟體即服務，透過網站提供，不需安裝。
    MVPMinimum Viable Product. The smallest version of the product that is still useful.最小可行產品，仍然有用的最精簡版本。

    3Analysis分析

    Break it down, examine it, and rebuild it. 拆解、檢視、再重建。

    The 3-step process三步驟流程

    ① Separate① 拆解
    • the problem問題
    • the demand ★需求 ★
    • the question疑問
    → into parts & components→ 拆成部分與元件
    →
    ② Investigate② 探究
    • potential relationships找出潛在關聯
    • investigate deeply, with evidence以證據深入探究
    →
    ③ Recombine③ 重組
    • rebuild into a clear whole重建成清楚的整體
    • e.g. Coggle (mind-map tool)例：Coggle（心智圖工具）

    The output must be產出必須是

    1 · Systematic1 · 系統化 2 · Structured2 · 結構化 3 · Process-oriented3 · 流程導向
    🔗 Link: the demand ★ feeds directly into the PRD (Stage 5). 🔗 關聯：需求 ★ 直接成為 PRD（階段 5）的內容。
    💡 These 3 steps can also describe how the BNA Agent handles business news: separate the news, investigate it with evidence, and recombine it into a summary. (Interpretation, not written in the original note.) 💡 這三步驟也可以用來說明 BNA Agent 處理商業新聞的方式：拆解新聞、以證據探究、重組成摘要。（此為詮釋，原筆記未寫明。）

    4Analytical Thinking分析性思考

    Check whether the problem can really be solved. 確認問題是否真的能被解決。

    “Can we really solve this problem?”「我們真的能解決這個問題嗎？」
    ✓ Effective: focus now✓ 有效：現在的重點 the goal / purpose is reached達成目標／目的
    ✗ Efficient: not yet✗ 效率：暫不追求 less input ↓ · more output ↑投入 ↓ · 產出 ↑
    💡 First make sure the solution works. Optimizing efficiency comes later, which matches the MVP mindset. 💡 先確保解決方案可行有效，之後再追求效率，這正符合 MVP 的思維。
